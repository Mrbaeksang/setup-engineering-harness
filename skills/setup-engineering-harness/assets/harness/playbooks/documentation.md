# Durable documentation

Create or update prose only when it will outlive this Task, change future behavior or decisions,
and has a canonical owner plus refresh/removal condition.

- Update the existing canonical location before creating a file.
- Record stable contracts, non-obvious constraints, operational commands, domain vocabulary, and
  consequential decisions.
- Prefer executable tests, types, schemas, and configuration when they already make the fact
  discoverable.
- Link to canonical sources instead of copying them.
- Remove or avoid progress reports, meeting notes, duplicated code narration, speculative
  roadmaps, raw research, and Task-specific result documents.

After a completed decision or implementation, update all affected canonical documents together;
do not leave contradictory stale guidance.
